# Host-smoke iteration 1 — findings (2026-09-04)

Harness: `npm run eval:hosts` (see `harness/`). Cases: `evals/host-cases/`.

## Coverage this iteration

- Hosts: claude, codex, pi (all three csd harnesses).
- Cases: structured-architecture (long), command-diagnosis (long, command/error
  preservation), terse-recommendation (short).
- Profiles: sailor, senior, glados. Intensity 2.
- ~20 real interactive sessions driven end to end.

## Preservation (hard-fail axis)

Held on every host and profile. No command, error string, path, code block, or
quote was altered. Codex collapses the two-line error to one line (whitespace
only; content intact) — worth a case-author note, not a violation.

## Recognizability by host

- **Claude**: strong across profiles. glados sustained clinical condescension
  through an entire long diagnosis; sailor and senior clearly voiced.
- **Pi**: good. senior strongly compressed; glados carried dry condescension
  through a long reply ("a small triumph for doing compilation before removing
  the compiler").
- **Codex**: host-dependent on reply length.
  - Short replies (terse-recommendation): glados clearly in voice across 3/3
    samples ("Redis will mostly cache your uncertainty").
  - Long replies (command-diagnosis): glados FAILS distribution across 4/4
    samples — markers appear only in the opening/closing sentence; the body is
    baseline technical prose. This is the rubric's explicit intensity-2 fail
    condition (markers detachable from opening/final paragraph).

## Root cause

Codex is built without `remindOnEveryActiveTurn` (`scripts/build.ts`), so unlike
Claude it emits no per-turn reinforcement. The activation card's influence decays
over a long generation, so subtle profiles wash out mid-reply. Short replies stay
close enough to the card to keep the voice.

## Candidate fix tested and REJECTED

Enabling `remindOnEveryActiveTurn` for Codex (one line in build.ts), verified on
3 long-case samples:

1. It **surfaces the reminder text** at the top of the parsed reply in 3/3
   samples (present in the transcript-derived turn; whether the Codex TUI shows
   it to the end user was not separately verified — csd's turn parser may be
   including injected context). Either way the reminder text ends up where reply
   content is read.
2. It **doesn't reliably fix distribution**: bodies stayed largely baseline even
   with the reminder present.

Reverted. Codex's quiet-ordinary-turns design stands.

## Iteration 2 — caveman-pattern persistence card (KEPT)

Precedent check (JuliusBrussee/caveman, `skills/caveman/SKILL.md`): caveman does
no per-turn injection at all. Its style directive is delivered once through the
host's native persistent instruction channel and carries an explicit persistence
block in the card itself ("ACTIVE EVERY RESPONSE. No revert after many turns. No
filler drift. Still active if unsure.").

Applied the same pattern to Mouthfeel's shared card prefix
(`src/core/profiles.ts`, `renderRuntimeCard`): the card now states that the
profile stays active for every future reply, applies to entire long/structured
replies (not only openings and closings), and that baseline-passing prose should
be rewritten before sending.

Results:
- codex-glados long case, n=3: improved from 4/4 bookend-only fails to marginal —
  mid-body markers now appear ("an impressive way to deploy half a program",
  "the test is suitably primitive"), but one of three samples is still
  bookend-only. Not yet a clean intensity-2 distribution pass.
- claude-glados long case, n=1 regression check: no over-projection; still an
  excellent sustained pass.
- No leak in any sample (nothing is injected per-turn); preservation intact
  everywhere.

Kept: strict improvement, host-agnostic, zero observed cost. Sampling was
bounded (codex n=3, claude n=1); a fuller promotion pass per the rubric's
refinement protocol (5+ samples, second-host verify) is still worth doing.

## Remaining gap and recommendation

Long Codex replies with subtle profiles are improved but still below the
intensity-2 distribution bar. The remaining lever, following caveman's delivery
model, is a Codex-native persistent instruction channel that is re-read every
turn without appearing in the visible transcript (caveman uses ~/.codex/AGENTS.md
— global, so unsuitable for Mouthfeel's per-session scope as-is; a session-scoped
equivalent on Codex is the thing to investigate). Loud profiles (sailor) and
short replies were never affected.

# Variant sweep — findings (2026-09-04, evening)

Full matrix: 18 profiles × intensities 1–3 × three arms (claude/sonnet-5,
claude/opus-5, codex/gpt-5.6-sol at csd-pinned low effort), gate case
structured-architecture, 163 sessions plus fix re-runs. Verdict table:
SWEEP-2026-09-04-verdicts.md. Review UI: the "Mouthfeel Voice Lab" artifact.

## Arm results

- **Opus 5: 18/18 clean**, correct progression everywhere — the reference arm.
- **Sonnet 5: i2/i3 pass on all 18; 9/18 over-projected at i1** (i1 read like
  i2). Fixed for 8/9 by (a) making the shared card's distribution sentence
  intensity-aware (i1 now says stay light / near-baseline) and (b) one i1
  restraint line each for caveman, jesse-pinkman, sopranos. Residual: caveman
  i1 on sonnet still breaks grammar despite explicit instruction (clean on
  opus); recorded, not further tuned.
- **codex/gpt-5.6-sol: uniform long-form flattening** — at most one detachable
  voiced clause per reply even for the loudest profiles; a medium-effort `-c`
  override probe barely helped, so this is model behavior, not the effort pin.
  Short replies remain in-voice (iteration-2 evidence). Recorded limitation;
  no card tuning attempted for this arm.

## Cross-cutting

- Preservation intact in every judged sample across all arms and fix runs.
- ~6/54 codex replies opened with "using the superpowers workflow" meta-
  narration from the worker environment — harness isolation improvement to do.
- Opus i1 regression check after the i1 fix: caveman, glados, sailor all still
  pass; the fix did not over-suppress.
